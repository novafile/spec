# NOVA conformance suite

The test vectors in this directory are dedicated to the public domain under [CC0-1.0](LICENSE).

Language-neutral test cases for implementations of the [specification](../SPEC.md). Inputs are plain NOVA text, binary encodings, schemas and patches. Expectations are JSON, so an implementation can run the suite before it can read NOVA metadata.

Expectations are generated by the reference implementation (`cargo run -p novafile-conformance -- generate DIR`) and reviewed by hand. Where an expectation and the specification disagree, the specification wins; please open an issue.

## Comparing values

Two values are equal when their **revisions** are equal (§2.13: SHA-256 of the canonical binary encoding). Expectations of successful cases contain:

| Field | Meaning | Normative |
| --- | --- | --- |
| `revision` | `sha256:<hex>` of the canonical encoding | **yes** — compare this |
| `binary` | Hex of the canonical encoding (§5.2) | **yes** for binary encoders |
| `canonical` | The canonical text (§4.10) | yes for canonical writers; useful for diffs |

Failure cases contain `"error"`. Whether a case fails is normative; error messages, and `line`/`col`, are informative only (other implementations may word errors differently or report a nearby position).

## Layout

| Directory | Each case | Expectation |
| --- | --- | --- |
| `text/valid/` | `NAME.nova` — a data document | `NAME.expect.json`: `revision`, `binary`, `canonical` of the parsed value |
| `text/invalid/` | `NAME.nova` — MUST be rejected | `NAME.expect.json`: `{"error": true, …}` |
| `binary/valid/` | `NAME.bin` — a value encoding (§5.1), possibly non-canonical (back-references, record lists, unsorted records) | as `text/valid` |
| `binary/invalid/` | `NAME.bin` — MUST be rejected by a decoder | `{"error": true, …}` |
| `schema/SCHEMA/` | `schema.novs`, plus documents in `valid/` and `invalid/`, and layers in `partial-valid/` and `partial-invalid/` | valid: the **resolved** value (§6.3, defaults and conversions applied; partial resolution for `partial-valid/`, §6.4); invalid: `issue_paths` (normative set of paths with issues) and `messages` (informative) |
| `schema-invalid/` | `NAME.novs` — a schema that MUST be rejected | `NAME.expect.json`: `{"error": true, …}` |
| `schema-names/` | `names.json`: a list of schema names | `expect.json`: an object mapping each name to `qualified`, `local` or `invalid` (§6.7) |
| `schema-lookup/CASE/` | a directory tree with `nova-catalog.nova`, `.novs` files and `doc.nova`, whose `@schema` reference is looked up without fetching (§6.9) | `expect.json`: `resolved` (the path of the chosen file, relative to the case, or `<builtin>`) and optional `warnings`, or `error`: `conflict`, `pin`, `not-found` |
| `schema-versions/CASE/` | `old.novs`, `new.novs` | `expect.json`: `kind` (`none`/`compatible`/`breaking`), `minimum` version, `accepted` (§6.5, §6.7) |
| `query/DOC/` | `doc.nova`, `queries.txt` (one path per line) | `expect.json`: per query the selected value, or `error`: `not-found`, `ambiguous`, `type`, `not-singular`, `invalid-path` |
| `patch/CASE/` | `doc.nova`, `op.patch` (applied without a schema) | `expect.json`: the patched value, or `error`: `syntax`, `stale-base`, `scope`, `op-failed` (with `op`, the failing operation's 1-based index), `invalid` |
| `template/CASE/` | `template.nova`, `args.nova` (a record of parameters) | `expect.json`: the rendered value, or `{"error": true, …}` |
| `lines/` | `NAME.novl` — a NOVA Lines stream (proposal 0002 §4.13), plus `NAME.novs` for positional streams | `NAME.expect.json`: as `text/valid` for the list of records read, plus `skipped` and `segments` (below) |
| `streams/` | `NAME.bin` — a binary record stream: frames with META `!header`/`!end` frames (proposal 0002 §4.3), plus `NAME.novs` for positional streams | as `lines/`; `skipped[].at` is a byte offset |

## Record streams

`lines/` and `streams/` cases are read in recovering mode: an invalid line or frame is skipped and reading continues. Their expectations add:

| Field | Meaning | Normative |
| --- | --- | --- |
| `skipped` | `at` (1-based line, or byte offset of the frame) and `message` per skipped line, frame or batched record | `at` yes; `message` no |
| `segments` | per segment: `count` of records read, `status` (`complete`: the end marker matches; `open`: no end marker; `corrupt`: it does not match) | `count` and `status` yes |

An invalid header directive (or `!header`) rejects its segment: its records are skipped until the next segment starts. A strict reader stops at the first skipped entry instead.

These cases follow a proposal, not yet the specification, and may change with it.

## Running the suite

The Rust reference implementation runs it with `cargo test -p novafile-conformance`, looking for this directory in `$NOVA_CONFORMANCE` or in a `spec/` checkout next to its repository.

A minimal runner for another implementation:

1. For every `text/valid/*.nova`, parse it, compute the revision, and compare with `revision`.
2. For every `text/invalid/*.nova`, parsing must fail.
3. Repeat for the other directories as far as the implementation goes. Partial conformance is fine; report which directories pass.

## Coverage

- **Text syntax (§4):** scalars and the strict number grammar, decimals at the edges of their range (the smallest exponent and 128-bit coefficient), rationals, typed literals including ISO 8601 durations, quoted and block strings, nested records and lists, flow values, tuples, sets, maps, variants with flow and block payloads, tables (dense and sparse), comments, directives, and every MUST-reject rule exercised by the reference parser.
- **Binary (§5):** canonical encodings of all valid text cases, plus non-canonical encodings that decoders must accept and malformed inputs that they must reject, including variant tags that are not identifiers (§2.11).
- **Schemas (§6):** lossless conversions, exact numeric `@range` (the binary64 value nearest 0.1 lies above the decimal bound 0.1), `@len` units, closed and `@open` records, `@key` uniqueness, `{tag: payload}` variants, map keys that become duplicates after conversion, field defaults that do not resolve or never terminate, ordered unions and quoted field names, keyed unions (uniqueness across members, and invalid schemas whose record members disagree on `@key`), and SemVer release checks (including union evolution, and `decimal` to `rational` as a breaking change).
- **String patterns and literal types (§6.1):** whole-string I-Regexp `@pattern` matching (`^` as a literal, `.` and line breaks, Unicode categories, map keys, `@len` together with `@pattern`), literal types in unions, tuples and `T?`, invalid patterns and attributes, unknown schema directives, and release checks for pattern and literal changes (§6.5).
- **Schema names and catalogs (§6.7, §6.9):** qualified and local names (hosts, labels, IP addresses, dot segments, the 255-byte limit), lookup through catalog directories, the newest readable version, fingerprint preference, conflicts, pin mismatches, the nearest project catalog, no fetching by default, and the legacy meta-schema name.
- **Paths, queries and patches (§7),** including a scope whose target cannot be removed.
- **Templates (§9),** including the output budget.
- **Record streams (proposal 0002):** NOVA Lines value, table (nested and rest columns, literal cells) and positional modes, comments, segments from concatenation, end markers, `@key` uniqueness, header errors (and a new segment after one); binary streams with batches, unknown META frames, corrupt and truncated frames.
